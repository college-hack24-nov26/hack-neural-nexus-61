# CropNex AI — Database Schema

## 1. Database Overview

* Database: SQLite
* ORM: SQLAlchemy
* Backend: Python FastAPI

The database stores crop information, AI detection results, IoT sensor readings, device information and agricultural recommendations.

## 2. Database Tables

### 2.1 Crops

| Column     | Data Type    | Constraints |
| ---------- | ------------ | ----------- |
| id         | INTEGER      | PRIMARY KEY |
| crop_name  | VARCHAR(50)  | NOT NULL    |
| variety    | VARCHAR(100) | NULL        |
| created_at | DATETIME     | NOT NULL    |

Purpose: Stores information about monitored crops.

### 2.2 Detections

| Column         | Data Type    | Constraints            |
| -------------- | ------------ | ---------------------- |
| id             | INTEGER      | PRIMARY KEY            |
| crop_id        | INTEGER      | FOREIGN KEY → crops.id |
| detection_type | VARCHAR(20)  | NOT NULL               |
| prediction     | VARCHAR(100) | NOT NULL               |
| confidence     | FLOAT        | NOT NULL               |
| image_path     | VARCHAR(255) | NOT NULL               |
| created_at     | DATETIME     | NOT NULL               |

Purpose: Stores disease and pest detection results generated by ML models.

### 2.3 Devices

| Column      | Data Type    | Constraints      |
| ----------- | ------------ | ---------------- |
| id          | INTEGER      | PRIMARY KEY      |
| device_id   | VARCHAR(50)  | UNIQUE, NOT NULL |
| device_name | VARCHAR(100) | NOT NULL         |
| status      | VARCHAR(20)  | NOT NULL         |
| last_seen   | DATETIME     | NULL             |
| created_at  | DATETIME     | NOT NULL         |

Purpose: Stores ESP32 device information and communication status.

### 2.4 Sensor Readings

| Column      | Data Type   | Constraints              |
| ----------- | ----------- | ------------------------ |
| id          | INTEGER     | PRIMARY KEY              |
| device_id   | INTEGER     | FOREIGN KEY → devices.id |
| sensor_type | VARCHAR(50) | NOT NULL                 |
| value       | FLOAT       | NOT NULL                 |
| unit        | VARCHAR(20) | NOT NULL                 |
| recorded_at | DATETIME    | NOT NULL                 |

Purpose: Stores environmental readings received from ESP32 sensors.

### 2.5 Recommendations

| Column         | Data Type   | Constraints                       |
| -------------- | ----------- | --------------------------------- |
| id             | INTEGER     | PRIMARY KEY                       |
| detection_id   | INTEGER     | FOREIGN KEY → detections.id, NULL |
| recommendation | TEXT        | NOT NULL                          |
| severity       | VARCHAR(20) | NOT NULL                          |
| created_at     | DATETIME    | NOT NULL                          |

Purpose: Stores agricultural recommendations generated by the advisory engine.

## 3. Database Relationships

1. One crop can have multiple detection records.
2. One detection can generate multiple recommendations.
3. One device can generate multiple sensor readings.
4. A recommendation can exist without a detection when generated from sensor conditions alone.

## 4. Data Validation Rules

* Detection confidence must be between 0 and 1.
* Detection type must be Disease or Pest.
* Recommendation severity must be Low, Medium or High.
* Device identifiers must be unique.
* Required fields cannot contain NULL values.
* Sensor readings must pass sensor-specific validation.

## 5. Database Technology

SQLite is selected for the initial hackathon prototype because it is lightweight and requires minimal configuration.

SQLAlchemy will manage database models and relationships through the FastAPI backend.

## 6. Scope

The initial database supports:

* Crop information.
* Disease and pest detection history.
* ESP32 device management.
* Environmental sensor readings.
* Agricultural recommendations.

Additional tables will be introduced only if required by the MVP.
